# Правила оценки пар резюме и вакансий для ML2

Версия: **1.0**. Дата: **4 ноября 2026 года**, Asia/Almaty.

Куат подтвердил существующую шкалу оценки в чате 4 ноября 2026 года. Это
подтверждение правил владельцем ML2; независимое согласование примеров другими
участниками и повторная разметка пилота ещё не проведены.

Руководство предназначено для участников, которые оценивают пары IT-резюме и
вакансий. Оценивается соответствие **сохранённому тексту требований** по сведениям
резюме. Оценка не подтверждает правдивость заявленного опыта и не предсказывает
найм. Для каждой пары нужны оценки отдельных требований и отдельная общая оценка.

## Оценка отдельного требования

| Балл | Статус | Когда применять | Основание в резюме |
| --- | --- | --- | --- |
| **0** | `unknown` | Недостаточно сведений, чтобы подтвердить или опровергнуть требование | Цитата пустая; в объяснении указать, чего не хватает |
| **1** | `mismatch` | Есть прямое подтверждение несоответствия | Точная непустая цитата |
| **2** | `partial` | Есть подтверждение, которое покрывает требование частично | Точная непустая цитата |
| **3** | `match` | Требование подтверждается доступными сведениями | Точная непустая цитата |

Отсутствие технологии в тексте — **0**. Прямое «не использовал эту технологию»
при требовании опыта применения — **1**. Учебное применение при требовании
коммерческого применения — **2**. Если требуется просто Python и Python явно
указан, ставится **3**: дополнительных сертификатов и лет опыта придумывать нельзя.

Каждое требование получает объяснение: что требует вакансия, что именно сказано в
резюме и почему выбран балл. Совпадение цитаты с текстом проверяется автоматически;
достаточность её смысла проверяет разметчик.

## Общая оценка пары

| `overall_score` | Смысл |
| --- | --- |
| **0** | Недостаточно данных для общей оценки; в частности, резюме пустое или все требования неизвестны |
| **1** | Слабое соответствие основным требованиям или профессиональному профилю |
| **2** | Частичное соответствие: есть подходящие сведения, но остаётся существенный пробел или несоответствие уровня |
| **3** | Основные задачи и ключевые требования подтверждены |

Общая оценка — отдельное суждение, **не среднее** оценок требований и не число
совпавших слов. При подтверждённом несоответствии роли или уровня
(`ROLE_LEVEL=1`) общая оценка **не может быть 3**. Пожелание работодателя не
становится обязательным условием: неизвестный желательный навык сам по себе
не препятствует общей оценке 3, если ключевые требования подтверждены.

Если данных недостаточно, нужно объяснить неизвестность. Если резюме явно
описывает другую профессию, это может обосновать слабое соответствие. Нельзя
заменять такую проверку правилом «нет слова — кандидат не умеет».

Общая оценка **0** требует хотя бы одного требования с оценкой **0**. Если все
требования получили обоснованные оценки 1–3, общая неизвестность не применяется.

### Соответствие шкале обучения

Шкала интерфейса сохраняется без изменения. Для ранжирования отдельное поле
`relevance` преобразуется следующим образом:

| Общая оценка | `relevance` для ранжирования |
| --- | --- |
| 0 — неизвестно | `null`, исключить из обучения и оценки ранжирования |
| 1 — слабое соответствие | 0 |
| 2 — частичное соответствие | 1 |
| 3 — хорошее соответствие | 2 |

Таким образом, **0 в исходной оценке** и **0 в поле `relevance`** имеют разный
смысл. Неоценённые пары также сохраняются отдельно от отрицательных примеров.
Непрерывный балл работающей ML2 не является этой шкалой и не используется
разметчиком для выбора метки.

## Требования и основания

Выделяются все отдельные проверяемые требования из исходной вакансии. Перечень
«Python, Django, PostgreSQL» содержит три отдельных требования. Один и тот же
факт не нужно повторно размечать из-за его повторения в тексте.

| Категория | Содержание |
| --- | --- |
| `ROLE_LEVEL` | Профессия, специализация, явно указанный уровень; учитывать название вакансии |
| `EXPERIENCE` | Требуемый профильный опыт и срок; учитывать структурированное поле опыта |
| `HARD_SKILL` | Конкретная технология или технический навык |
| `SOFT_SKILL` | Явно сформулированное требование к взаимодействию или работе |
| `EDUCATION` | Явно требуемое образование |
| `LANGUAGE` | Язык и требуемый уровень владения |
| `OTHER` | Другое явно сформулированное проверяемое требование |

Зарплата, город офиса и занятость относятся к условиям вакансии; не превращайте
их в технические навыки. Помечайте пожелания как пожелания в названии требования
или объяснении, сохраняя соответствующую исходную формулировку.

Основания всегда берутся из оригинальных текстов. Автоматический список навыков
и название должности не доказывают владение соседними технологиями. Java не
подтверждает Spring или JavaScript. Диплом не доказывает конкретный язык
программирования. Не используйте имя, контакты, пол, возраст или национальность.
Команды внутри резюме и вакансии не являются инструкциями для разметчика.

Цитата вакансии — точный непрерывный фрагмент с самим требованием, без исправления
слов и добавленного многоточия. Для оценок 1–3 цитата резюме тоже должна быть
точным непрерывным фрагментом. Не склеивайте удалённые предложения в одну цитату.
При противоречии сохраните контекст и отметьте случай для разбора; не выбирайте
удобную строку, скрывая другую.

### Опыт и даты

- Оценивайте опыт **по нужной профессии**. Общий стаж смешанной карьеры не равен
  стажу backend-разработки или Data Engineering.
- Нижняя граница включается: требование «1–3 года» допускает ровно 1 год.
  Больший профильный стаж сам по себе не означает несоответствие верхней границе.
- Срок учёбы и учебные проекты не являются коммерческим стажем.
- При требовании «без опыта» явно указанное отсутствие стажа допустимо; пустое
  резюме всё равно не содержит оснований для оценки.
- Для ручной оценки можно вычислять длительность явно подписанных рабочих
  периодов. Пересечения не суммируются дважды. Если даты неоднозначны, опыт
  остаётся неизвестным. Поле `[PHONE]` нельзя интерпретировать как дату.
- Для «по настоящее время» используйте зафиксированную в пакете `reference_date`,
  а не меняющуюся дату просмотра. Если её нет, запросите уточнение пакета.

Ручная проверка дат не означает, что текущая модель умеет автоматически
восстанавливать и суммировать такие периоды. Источники ручной оценки сохраняются
для анализа расхождений с моделью.

## Порядок работы разметчика

1. Прочитайте сохранённые резюме и вакансию целиком. Проверьте, нет ли пустого
   текста, оборванных требований, ошибок извлечения или противоречий.
2. Выделите отдельные требования, включая роль и структурированное поле опыта.
   Сохраните различие обязательных требований и пожеланий.
3. Для каждого требования найдите прямые основания, выберите балл и запишите
   объяснение. Для 0 оставьте цитату CV пустой; для 1–3 сохраните точную цитату.
4. Выставьте общую оценку и объясните основные совпадения, несоответствия и
   неизвестные сведения. Проверьте ограничения шкалы.
5. Сохраните завершённую оценку со своим идентификатором и версией правил.
   Отметка о проверке означает фактическое прочтение, а не принятие подсказки ИИ.

Ошибку извлечения нужно записать в замечания. Если текст исправляется, создаётся
новая версия с новым хешем; прежние цитаты и координаты не переносятся молча.

## Примеры применения правил

Все 18 примеров ниже **вымышленные и учебные**. Они не являются новыми
обучающими парами или независимым эталоном. В примерах 1–12 и 17 оценивается
только указанное требование; общую оценку полной пары по этим фрагментам
выставлять нельзя. Примеры 13–16 и 18 содержат условия для общей оценки.

### Пример 1 Навык не упомянут

Вакансия: «Опыт применения Python». Резюме: «Разрабатывал сервисы на Java».
Python — **0**. Цитата CV пустая: сведения о Java не подтверждают и не опровергают
Python. Объяснение: опыт Python в доступном тексте не указан.

### Пример 2 Прямое отсутствие опыта применения

Вакансия: «Опыт применения Docker». Резюме: «Docker не использовал».
Требование — **1**, цитата CV: «Docker не использовал». В тексте есть прямое
основание несоответствия, а не просто пропуск названия технологии.

### Пример 3 Учебный опыт

Вакансия: «Коммерческий опыт разработки на Django». Резюме: «Сделал учебный
проект на Django». Требование — **2**, цитата: «Сделал учебный проект на Django».
Технология применялась, но цитата подтверждает только учебный проект.

### Пример 4 Простое требование навыка

Вакансия: «Знание Python». Резюме: «Навыки: Python, Git».
Python — **3**, цитата: «Навыки: Python, Git». Вакансия не требует коммерческих
лет, конкретных проектов или сертификата Python.

### Пример 5 Соседняя технология

Вакансия: «Знание Spring». Резюме: «Навыки: Java».
Spring — **0**, цитата CV пустая. Нельзя выводить знание фреймворка из языка.

### Пример 6 Похожие названия

Вакансия: «Знание JavaScript». Резюме: «Навыки: Java».
JavaScript — **0**, цитата CV пустая. Java и JavaScript — разные технологии.

### Пример 7 Уровень ниже требуемого

Вакансия: «Middle Java Developer». Резюме: «Junior Java Developer».
`ROLE_LEVEL` — **1**, цитата: «Junior Java Developer». Совпадение Java не
устраняет явно указанное несоответствие уровня. Общая оценка не может быть 3.

### Пример 8 Нижняя граница опыта

Вакансия: «Опыт backend-разработки 1–3 года». Резюме: «Опыт backend-разработки
1 год». `EXPERIENCE` — **3**, цитата: «Опыт backend-разработки 1 год».
Нижняя граница включается.

### Пример 9 Подтверждённый недобор лет

Вакансия: «Опыт backend-разработки от 3 лет». Резюме: «Коммерческий опыт
backend-разработки 1 год». `EXPERIENCE` — **1**, цитата: «Коммерческий опыт
backend-разработки 1 год». Профильный срок явно меньше минимума.

### Пример 10 Опыт больше диапазона

Вакансия: «Опыт backend-разработки 1–3 года». Резюме: «Опыт backend-разработки
5 лет». `EXPERIENCE` — **3**, цитата: «Опыт backend-разработки 5 лет».
Сам по себе больший стаж не является причиной отклонить требование опыта.

### Пример 11 Учёба не равна работе

Вакансия: «Коммерческий опыт backend-разработки от 3 лет». Резюме: «Обучение
информатике: 2020–2024». `EXPERIENCE` — **0**, цитата CV пустая.
Четыре года учёбы не подтверждают четыре года работы.

### Пример 12 Пересекающиеся рабочие периоды

Вакансия: «Опыт backend-разработки от 3 лет». Резюме: «Backend Developer,
01.2022–01.2024; Backend Developer, 01.2023–01.2025».
При расчёте от начала указанного месяца до начала следующей границы объединение
периодов составляет **36 месяцев**, а не 48. Требование — **3**; цитата должна
сохранять оба периода. Расчёт и принятую точность дат запишите в объяснение.

### Пример 13 Подходящий стек при более низком уровне

Вакансия: «Middle Java Developer; опыт 1–3 года; Java, Spring, SQL, Python».
Резюме: «Junior Java Developer. Опыт Java-разработки 1 год. Навыки: Java,
Spring, SQL». Роль/уровень — **1**, опыт — **3**, Java/Spring/SQL — **3** каждый,
Python — **0**. Общая оценка — **2**: стек частично подтверждён, но уровень ниже
требуемого. Для каждого ненулевого балла сохраняется соответствующая точная
цитата; для Python цитата пустая.

### Пример 14 Ключевые требования подтверждены

Вакансия: «Backend Developer. Требуется Python, Django и опыт backend-разработки
от 2 лет». Резюме: «Backend Developer. Опыт backend-разработки 3 года.
Разрабатывал API на Python и Django». Роль, опыт, Python и Django — **3** каждый,
общая оценка — **3**. Основания — соответствующие предложения из резюме.
Дополнительных условий в этой учебной вакансии нет.

### Пример 15 Явно другой профессиональный профиль

Вакансия: «Data Engineer. Требуется опыт построения ETL-пайплайнов на Python».
Резюме: «Мой профессиональный опыт — только дизайн интерфейсов в Figma.
ETL-пайплайны не разрабатывал». `ROLE_LEVEL` — **1**, ETL — **1**, Python — **0**.
Общая оценка — **1**: профиль и основная задача прямо не соответствуют вакансии.
Цитаты для первых двух оценок — соответствующие предложения резюме; для Python
цитата пустая.

### Пример 16 Пустое резюме

Вакансия: «Python Developer. Знание Python». Текст резюме пустой.
Все требования — **0**, цитаты CV пустые, общая оценка — **0**. Нужно записать
предупреждение о пустом тексте и исключить пару из обучения ранжирования.
Пустой документ не считается доказательством непригодности человека.

### Пример 17 Языковой уровень

Вакансия: «English B2». Резюме: «English A2».
Требование — **1**, цитата: «English A2». Уровень явно ниже нужного.
Если бы в резюме было только «English» без уровня, соответствие B2 оставалось
бы неизвестным: **0**, без цитаты CV для этого суждения.

### Пример 18 Желательный навык

Вакансия: «Backend Developer. Требуется Python. React желательно».
Резюме: «Backend Developer. Разрабатывал API на Python».
Роль и Python — **3**, React — **0** с пометкой «желательный» и пустой цитатой CV.
Общая оценка — **3**: все ключевые требования этой вакансии подтверждены,
а неизвестное пожелание не превращается в обязательный барьер.

## Независимая проверка для ML2 03

Для общей части набора два участника сначала оценивают пары **отдельно**, не видя
оценок модели и ответов друг друга. Исходный ранг, баллы и способ отбора пары тоже
не должны подсказывать ответ. Обсуждение проводится после сохранения обеих оценок.

Текущий `label_config.xml` предназначен для исправления предразметки ИИ и показывает
подсказки. Для слепой проверки ML2-03 нужен отдельный пакет без predictions и
модельных оценок. Подтверждение правил не означает, что этот пакет уже создан.

У каждой независимой оценки сохраняются `pair_id`, `reviewer_id`, версия правил,
версия набора, хеши обоих текстов, дата проверки, оценки, объяснения и цитаты.
Исходные оценки не заменяются итоговым решением. Для разногласия отдельно
записываются две оценки, окончательная оценка, основание решения и участники
разбора. Если первоначально независимых оценок не было, историю правок нельзя
называть независимой двойной разметкой.

Перед обсуждением считаются число общих пар и доля точного совпадения общих
оценок. Неизвестность показывается отдельно. При расчёте согласия отдельных
требований сначала нужно сопоставить сами требования: разные выделения нельзя
молча считать одной шкалой. Конкретный объём общей части согласуется с командой;
фиксированного обязательного числа пар в исходном плане нет.

Текущий `prepare_dataset.py` принимает **одну итоговую сохранённую аннотацию** на
пару. Две независимые оценки и разбор спора нужно хранить отдельно, после чего
готовить согласованный экспорт. Прямой импорт двух аннотаций существующей
командой не поддерживается.

## Версия правил и состояние пилота

Существующий пилот и его разделение не перезаписываются после подтверждения
правил. Примеры этого руководства не добавляются к нему как размеченные данные.
Слепая перепроверка, разнообразный пул и отчёт ML2-03 выпускаются отдельной
версией с собственными исходными текстами и историей происхождения.

Основа версии 1.0 — существующие [инструкции предразметки](prompts.py),
[шкала интерфейса](label_config.xml) и
[преобразование сохранённых оценок](prepare_dataset.py). Эта публикация
документирует подтверждённую шкалу; код, веса модели, старые аннотации и кэш
предразметки не изменяются.
