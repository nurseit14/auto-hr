# Проверки ML1-02, ML1-03 и ML1-04

Из корня репозитория, в окружении с `numpy` и `pandas`:

```bash
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s ML1/tests -v
git diff --check
```

Тесты используют временные CSV и матрицы. Encoder заменён заглушкой;
загрузка модели, API-ключи и настоящие резюме не нужны.

## ML1-02: идентификаторы вакансий

`JobMatcher` возвращает исходный `vacancy_id` как строку, сохраняя ведущие
нули, большие числа и буквальные `NA`/`null`. Поле `index` обозначает позицию
в матрице. Отсутствующие, пустые и повторяющиеся ID, пробелы по краям вызывают
ошибку. Проверяются связь ID с полями вакансии и неизменность ранжирования
при согласованной пересборке строк и векторов.

## ML1-03: версия и целостность индекса

Сборка создаёт два локальных файла:

- `data/processed/vacancy_embeddings.npy` — матрица;
- `data/processed/vacancy_embeddings.manifest.json` — метаданные и хеши.

```bash
python -m ML1.build_vacancy_embeddings
python -m ML1.validate_index
```

Первая команда использует модель; вторая проверяет индекс без загрузки модели.
Matcher выполняет ту же проверку при создании `JobMatcher`.

Проверки покрывают изменение текста, навыков, названия и ID, перестановку
строк без изменения количества, подмену векторов, неверные настройки модели,
отсутствующие и повреждённые файлы, размерность, тип, нормализацию, числовые
значения, прерванную публикацию и изменение CSV во время построения.
Успешная пересборка после изменения источника также проверяется.

Старую матрицу нельзя снабжать метаданными задним числом: неизвестно, из
какого CSV она получена. Её нужно пересоздать командой сборки. При любом
изменении байтов CSV (включая форматирование) потребуется пересборка.

Имя модели фиксируется в метаданных; revision весов и версии библиотек пока
не закреплены. `index_version` идентифицирует содержимое артефакта, но не
гарантирует воспроизводимость весов при обновлении модели на Hugging Face.
Параллельные сборки не поддерживаются: при несовпадении пары файлов загрузчик
выдаст ошибку и предложит пересборку.

Матрица и manifest являются локальными артефактами. В Git добавляйте явно
перечисленные исходники и тесты. Остальные участники пересобирают индекс у себя.


## ML1-04: общие настройки и граничные случаи

`MatchingConfig` задаёт единые defaults: alpha=0.4, confidence_target=5,
top_k=10. Оба CLI поддерживают `--alpha`, `--confidence-target`, `--top-k`.
Тесты проверяют одинаковые результаты реальных entrypoints при одном
обработанном тексте и конфигурации (PDF parser и encoder заменены заглушками).
Проверяются недопустимые параметры, NaN/Inf, пустой текст и корпус,
отсутствие навыков, граничные веса 0/1, top_k больше корпуса и фактическая
формула в контексте ассистента. API не вызывается.

Для ML1-04 переиндексация не нужна. При отсутствии skills веса остаются
фиксированными: это прежний baseline, а не новый эксперимент.
