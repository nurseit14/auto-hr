# ML1-02: идентификаторы вакансий

`JobMatcher` возвращает `vacancy_id` из исходного CSV как строку. Раньше
использовался столбец `id`, а при его отсутствии — номер строки.
Поле `index` по-прежнему обозначает позицию в матрице эмбеддингов.

Загрузчик сохраняет ведущие нули, большие числовые ID и буквальные значения
`NA`/`null`. Отсутствующий столбец, пустые ID, пробелы по краям и дубликаты
вызывают `ValueError` до загрузки матрицы. Некорректные ID нужно исправить
в источнике; новые идентификаторы автоматически не генерируются.

## Проверка

Из корня репозитория, в окружении с `numpy` и `pandas`:

```bash
python -m unittest discover -s ML1/tests -v
git diff --check
```

10 тестов используют временные CSV и матрицы, а encoder заменён заглушкой.
Загрузка модели, API-ключи и настоящие резюме не нужны. Проверяются точные
строковые ID, приоритет над старым `id`, связь с полями вакансии, валидация,
перестановка строк вместе с векторами и проверка количества векторов.

Дополнительно при реализации проверены все 1017 строк опубликованного
`vacancies_with_skills.csv`: выходные ID, названия, тексты и URL совпадают
с источником. Локальная матрица `(1017, 384)` загрузилась; семантические
оценки в этой проверке заменены нулями. Это проверка идентичности записей,
а не качества модели или соответствия содержимого каждого вектора.

## Следующий шаг

ML1-03 должен связать матрицу с конкретной версией CSV через метаданные
индекса. Сейчас перестановка только CSV без соответствующей перестановки

не решает; формула ранжирования и веса не изменены.
