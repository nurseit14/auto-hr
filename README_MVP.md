# Auto-HR MVP

Рабочее веб-приложение для первичного подбора **IT-специалистов в Казахстане**. HR создаёт вакансию, добавляет резюме, проверяет объяснение соответствия, уточняет опыт кандидата и формирует shortlist. Отдельный сценарий помогает кандидату найти IT-вакансии по своему резюме.

Фронтенд React и TypeScript работает с FastAPI через единый API. Резюме, уточнения, ручные исправления, решения HR и обратная связь сохраняются в SQLite. Исходные исследовательские модули `NLP`, `ML1` и `ML2` сохранены; их устройство описано в исходном `README.md`.

## Быстрый запуск на Mac

Для проверенного окружения нужны **Python 3.12+**, **Node.js 22.12+** и npm. При первом запуске нужен интернет для установки библиотек. Для основного сценария API-ключ не нужен.

Откройте терминал в папке проекта:

```sh
./start.command
```

Можно также открыть `start.command` двойным щелчком в Finder. Скрипт создаёт `.venv`, устанавливает зависимости, собирает интерфейс и запускает приложение:

**[Открыть Auto-HR](http://127.0.0.1:8000)**

Остановка — `Ctrl+C` в терминале. При повторном запуске неизменившиеся зависимости не переустанавливаются. Если порт занят:

```sh
./start.command --port 8001
```

Если зависимости и интерфейс уже подготовлены:

```sh
./start.command --skip-install --no-build
```

Для установки и сборки без запуска сервера:

```sh
./start.command --prepare-only
```

На Linux или Windows запускайте тот же переносимый скрипт через Python: `python3 scripts/start.py` или `python scripts/start.py`. В Windows среда создаётся в `.venv\Scripts`.

## Вход и кабинеты

Одна страница входа определяет кабинет по учётной записи; отдельного выбора роли нет.

| Логин | Пароль | Кабинет |
| --- | --- | --- |
| `admin` | `admin` | HR |
| `user` | `user` | Кандидат |

Это готовые демонстрационные аккаунты локального прототипа. Данные каждого аккаунта сохраняются после выхода и повторного входа, в том числе в другом браузере. Два входа под одним логином открывают одно рабочее пространство. Кнопка «Выйти» завершает текущий вход.

Кандидату доступны каталог IT-вакансий, подбор вакансий по своему резюме, загрузка и удаление собственных резюме, разбор резюме и вопросы о выбранной вакансии и балле. HR дополнительно управляет подбором кандидатов, создаёт и удаляет свои вакансии и загружает описание вакансии из PDF/DOCX/TXT. Перед сохранением загруженной вакансии HR проверяет и редактирует извлечённые поля. Созданные HR вакансии видны кандидату в общем каталоге.

Резюме двух кабинетов хранятся раздельно. Поиск подходящих вакансий сам по себе не передаёт резюме другому аккаунту и не создаёт отклик. Кандидат не получает доступ к чужим резюме, HR-решениям или созданию вакансий через API. Разделение проверяется сервером, а не только меню интерфейса.

### Разбор резюме и вопросы

Разбор показывает сильные стороны доступного текста, неподтверждённые требования и рекомендации: какие реальные проекты, задачи и сроки стоит уточнить. При выборе вакансии используется тот же расчёт ML2, что и в подборе, с 15 вкладами и отдельным правилом профильного стажа. Без вакансии это разбор содержимого резюме, а не оценка соответствия неизвестной работе.

Помощнику можно задать вопрос о требованиях, стаже, зарплате, месте работы или причинах балла. Ответ строится локально по сохранённой вакансии, выбранному собственному резюме и расчёту модели. Если зарплата или другая информация не указана, помощник сообщает об этом. Он не связывается с работодателем и не подтверждает актуальность архивной публикации. Вопросы и ответы хранятся отдельно от резюме: они не становятся опытом кандидата, признаками ML2 или обучающей разметкой.

## Как проверить MVP

### Подбор кандидатов для HR

1. Откройте «Подбор кандидатов». Для быстрого знакомства загрузите демонстрационные данные: это явно обозначенные вымышленные кандидаты и тестовая IT-вакансия.
2. Создайте свою IT-вакансию: укажите должность, компанию, город, опыт и технические требования.
3. Добавьте резюме текстом или загрузите PDF, DOCX либо TXT. В форме явно указана вакансия назначения: при загрузке из подбора по умолчанию выбрана текущая вакансия. В разделе «Все кандидаты» можно сохранить резюме в общей базе без назначения. Файл — до 8 МБ, текст — до 60 000 символов, PDF — до 40 страниц. TXT нужен в UTF-8. Для сканированного PDF без текстового слоя понадобится распознанный текст; MVP не выполняет OCR. PDF с паролем нужно предварительно сохранить без шифрования.
4. Подбор включает только кандидатов, явно добавленных к выбранной вакансии. Действие «Добавить из базы» позволяет выбрать существующие резюме. Один кандидат может участвовать в нескольких вакансиях после явного добавления; автоматического включения всей базы нет. Все кандидаты выбранной вакансии доступны для проверки, включая тех, кто расположен ниже в списке.
5. Откройте кандидата: сравните подтверждённые навыки, неподтверждённые требования и фрагменты резюме. В блоке «Из чего сложился балл» показаны вклад каждого признака, основания и итог. Общий стаж, подтверждённый профильный стаж и минимум вакансии отображаются отдельно. «Не подтверждено» означает отсутствие достаточного свидетельства в тексте, а не отсутствие навыка у человека.
6. Задайте уточняющий вопрос по требованиям вакансии и сохраните ответ. Ответ — самоотчёт кандидата, который HR должен проверить.
7. При необходимости исправьте список навыков и заметки. Повторите подбор, чтобы учесть изменения.
8. Сохраните решение HR: добавить в shortlist или оставить на рассмотрении. Приложение не отправляет автоматические отказы.
9. Выгрузите результат в CSV. Его можно открыть в Excel, Numbers или Google Sheets. Оцените полезность подбора через форму обратной связи.

### Удаление и назначения

- «Убрать из вакансии» снимает назначение и решение HR только для текущей вакансии. Резюме остаётся в общей базе и в других назначенных вакансиях.
- «Удалить резюме» после подтверждения удаляет кандидата, уточнения, назначения, решения и связанный отзыв из рабочего пространства.
- Созданную вами вакансию можно удалить из каталога или из текущего подбора. Её назначения и решения удаляются, а сами резюме сохраняются. Архивные вакансии исходного датасета не удаляются.
- При обновлении старой базы прежние резюме сохраняются. Назначения восстанавливаются только по уже сохранённым решениям HR; остальные резюме остаются в общей базе. Добавьте нужных кандидатов к вакансии действием «Добавить из базы».

### Вакансии для кандидата

1. Добавьте резюме в «Все кандидаты» или используйте уже сохранённое.
2. Перейдите в «Вакансии для кандидата» и выберите резюме.
3. Получите ранжированный список IT-вакансий с совпадающими и неподтверждёнными навыками.
4. Просмотрите требования и исходную ссылку вакансии. Свежесть и доступность публикации необходимо проверить у источника.

«Каталог вакансий» содержит **1 017 архивных IT-вакансий из исходного датасета, преимущественно 2023 года**. Это материал для проверки прототипа, а не обновляемая лента трудоустройства. Вакансии, созданные HR в приложении, хранятся отдельно в его рабочем пространстве.

## Что именно делает ML

1. **NLP:** исходный словарь `NLP.skill_extractor` извлекает и нормализует IT-навыки. Модуль анонимизации маскирует распознаваемые контактные данные. Его результат нужно проверять перед использованием реальных персональных данных.
2. **ML1:** повторно используются сравнение навыков и объяснение совпадений. При отсутствии индекса эмбеддингов работает явно обозначенный лексический и навыковый baseline. Он не называется семантической моделью.
3. **ML2:** локально обученный `LinearRanker` v3 из `backend/models/ranker.json` сравнивает 15 профессиональных признаков резюме и вакансии. Он отдельно учитывает нужные навыки без пожеланий и навыки в описанных задачах. Обучение включает сравнения кандидатов для одной вакансии и вакансий для одного CV. Общий стаж и слово Middle сами по себе не дают прибавку за нерелевантный опыт; смешанные роли и неподтверждённые сроки не превращаются в профильные годы автоматически. Каждый вклад в балл доступен вместе с причиной и исходным фрагментом.
4. **HR:** проверяет исходные фрагменты, корректирует извлечение, учитывает уточнения и принимает окончательное решение.

**Балл ML2 — не вероятность найма, не процент пригодности и не оценка человека.** Это экспериментальная модель: баллы полезны для сравнения кандидатов по одной вакансии или вакансий для одного резюме. Покрытие навыков — отдельный показатель. Результат зависит от полноты резюме, словаря навыков и обучающей выборки. Качество по русскому, казахскому и английскому языкам ещё нужно измерять отдельно.

У текущей версии нулевые признаки дают нулевой балл: применяется масштабирование, рассчитанное по train, без вычитания среднего. Это объяснимая точка отсчёта, а не порог найма. Вклады рассчитываются самой линейной моделью. Отдельное явно обозначенное правило учитывает подтверждённый недобор профильного стажа: положительная часть исходного балла умножается на долю выполнения минимального стажа. Например, 1 профильный год при минимуме 3 года оставляет треть положительного балла. Неизвестный стаж не превращается в нулевой стаж и не вызывает эту поправку. Отрицательный исходный балл правило не повышает. Сайт показывает исходную сумму, поправку и итог; правило не выдаётся за обученный коэффициент. Нулевой коэффициент признака явно означает, что его самостоятельного вклада нет. Исторические веса первой версии сохранены отдельно в `backend/models/ranker-v1.json` и не используются текущим сайтом.

V3 обучена на прежних 155 парах, включая 132 сравнения вакансий и 34 сравнения кандидатов. Настройки выбраны по трём разделениям train по кандидатам; после исправления выявленных отрицаний они оставались зафиксированными. На свежей синтетической HR-проверке из 8 вакансий и 48 профилей NDCG@5 выросла с 0,9481 у v2 до 0,9716, попарная точность — с 0,8490 до 0,9010. Это инженерные примеры, не результаты настоящих HR-пользователей. На историческом тесте вакансий для резюме прирост небольшой: 0,7142 → 0,7171; отдельная validation снизилась 0,9421 → 0,9096. Универсальное улучшение не доказано. Агрегаты и история первого теста сохранены в `backend/models/ranker-v3-evaluation.json` и `backend/models/hr-ranking-v3-evaluation.json`; подробности — в `ML2/README.md`.

Готового ML1-индекса эмбеддингов в исходной папке нет. Исследовательский код его подготовки сохранён в `ML1/build_vacancy_embeddings.py`; он требует дополнительных зависимостей и загрузки модели. Подключение ML1 включается явно через `AUTO_HR_ENABLE_ML1=1` после подготовки индекса и установки его зависимостей. Текущий режим приложения проверяйте через `/api/health`. Основной MVP не требует OpenAI API, отправки резюме внешней LLM или платных запросов.

## Структура

```text
frontend/                         React + TypeScript + Vite
backend/                          FastAPI, SQLite, обработка файлов и API
backend/models/ranker.json        обученные веса существующего ML2
backend/tests/                    интеграционные тесты API
backend/requirements.lock        версии проверенного окружения бэкенда
NLP/                              словарь навыков и обработка резюме
ML1/                              навыковый и семантический pipeline
ML2/                              признаки и обученный линейный ranker
data/processed/vacancies_with_skills.csv
scripts/start.py                  установка, сборка и запуск
start.command                     запуск на Mac
.github/workflows/mvp.yml         тесты и сборка при push и pull request
```

В приложение скопирован только файл весов ML2. Частные резюме, исходные аннотации, `.env` и ключи из исходной папки не нужны для запуска и не входят в образ Docker.

## Разработка

На Python 3.12 или новее один раз установите зависимости из файла проверенных версий:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock
npm --prefix frontend ci
```

В первом терминале:

```sh
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --reload
```

Во втором терминале:

```sh
npm --prefix frontend run dev -- --host 127.0.0.1
```

Откройте адрес, напечатанный Vite. Его прокси направляет `/api` на бэкенд `127.0.0.1:8000`, поэтому обе части используют одну сессию. Собранный интерфейс обслуживает сам FastAPI; отдельный Node-сервер после сборки не нужен.

Базовые тесты API и сборка интерфейса:

```sh
.venv/bin/python -m pytest -q backend/tests
npm --prefix frontend run build
```

Для полного прогона существующих ML1/ML2-регрессий дополнительно нужны pandas и пакет OpenAI SDK. Эти тесты подменяют внешние вызовы; ключ и загрузка эмбеддингов не требуются:

```sh
.venv/bin/python -m pip install 'pandas>=2,<3' 'openai==1.109.1'
.venv/bin/python -m pytest -q backend/tests ML1/tests ML2/tests
```

В текущей сборке полный прогон завершился успешно: **347 тестов и 66 проверок subtest**. Также прошла сборка TypeScript/Vite. В браузере проверены демонстрационный сценарий, уточнение опыта, ручная правка навыков, решение HR, CSV, создание IT-вакансии, добавление и удаление текстового резюме, поиск в каталоге, подбор вакансий, отзыв и сохранение данных после обновления страницы. Для назначений дополнительно проверены раздельные списки двух вакансий, добавление из общей базы, снятие назначения с сохранением решения в другой вакансии, удаление вакансии без потери резюме, загрузка TXT с частичной ошибкой пакета, фильтр «Без вакансии», мобильный вид 390 px и сообщение о сбое обновления после успешного изменения.

Для кабинетов дополнительно проверены ошибочный пароль, вход и выход обоих аккаунтов, запрет HR-действий прямым запросом кандидата, импорт TXT-вакансии с проверкой полей и её появление в каталоге кандидата, личная загрузка TXT-резюме, подбор 10 вакансий, разбор без вакансии и с ней, ответы о балле и зарплате с источниками, сохранение истории после обновления и разделение резюме и вопросов между аккаунтами. Страница входа и кабинет кандидата проверены на ширине 390 px и на настольном экране. Эти технические проверки не заменяют beta-тест реальными пользователями.

Для ML2 v3 в браузере проверен исходный случай Middle Data Engineer (SAP/Tableau): все четыре непрофильных деморезюме получают 0. Отдельный синтетический пример с 6 общими годами и 1 годом Data Engineering показывает 1 профильный год при минимуме 3, положительную исходную сумму и явную поправку до трети. Доступны все 15 вкладов, цитаты с реальными источниками, отдельное правило и точный итог. Дополнительно проверен порядок: описание работы с нужными Python/FastAPI выше простого списка этих навыков, оба выше нерелевантного frontend со стажем 8 лет и одним желательным React. Отрицание опыта работы с Docker не превращается в подтверждение; отрицание опыта потоков данных не подтверждает профиль Data Engineering. Такой же разбор открывается в подборе вакансий; мобильная страница 390 px не имеет горизонтального переполнения. Тесты подтверждают поведение на проверенных формулировках, а не универсальную точность извлечения или реальную экономию времени HR.

Workflow `.github/workflows/mvp.yml` запускает эти регрессии на Python 3.12 и сборку на Node.js 22.12 при push и pull request. Для ML-проверок отключена загрузка моделей; секреты и платные API не используются. Успешный локальный прогон не означает, что удалённый GitHub Actions уже запускался.

Документация API доступна на [локальной странице Swagger](http://127.0.0.1:8000/docs). Ключевые маршруты: `/api/auth/me`, `/api/auth/login`, `/api/auth/logout`, `/api/vacancies`, `/api/vacancies/import-preview`, `/api/candidates`, `/api/candidates/{id}/feedback`, `/api/questions`, `/api/shortlist`, `/api/matches`, `/api/reviews`, `/api/export`, `/api/feedback` и `/api/health`.

## Хранение и доступ

Это **локальный MVP** с двумя готовыми демонстрационными аккаунтами. Регистрация и подтверждение компании не предусмотрены. Сервер проверяет вход, роль и принадлежность резюме аккаунту; роль не принимается из полей формы или браузерного хранилища. Запуск по умолчанию доступен только на этом компьютере, через `127.0.0.1`.

SQLite по умолчанию хранится в `backend/runtime/auto_hr.sqlite3`. Путь можно изменить переменной окружения `AUTO_HR_DB`. Пример параметров — `.env.example`; скрипт не загружает `.env` автоматически. Данные сохраняются между перезапусками и входами. Для удаления резюме используйте действие удаления кандидата. Очистка cookie завершает доступ в текущем браузере, но не удаляет записи аккаунта: после повторного входа они снова доступны.

Пароли в базе хранятся с солью и PBKDF2, токены входа — как хеши с серверным сроком действия 30 дней. Cookie входа `autohr_auth` имеет HttpOnly и SameSite Strict; выход отзывает текущий токен на сервере. Готовые пары `admin/admin` и `user/user` предназначены для локальной демонстрации. Для внешнего пилота нужны индивидуальные учётные записи и пароли, HTTPS, восстановление доступа, сроки хранения и согласованный порядок обработки персональных данных.

При первом подходящем входе HR прежнее рабочее пространство этого браузера переносится в аккаунт `admin` по старой cookie. Другие старые пространства не объединяются автоматически. Вход кандидата не получает старые HR-резюме и не расходует возможность последующего переноса HR. Перед обновлением сохранена резервная копия локальной базы.

## Docker

При установленном Docker:

```sh
docker compose up --build
```

Приложение: [http://127.0.0.1:8000](http://127.0.0.1:8000). База хранится в именованном томе `auto-hr-data`; порт привязан к локальному интерфейсу компьютера. Остановка контейнера через `docker compose down` сохраняет базу. Команда `docker compose down --volumes` удалит данные этого тома.

Конфигурация проверена командой `docker compose config --quiet`. Сборка образа и запуск контейнера в ходе этой проверки не выполнялись.

| Требование MVP | Реализация |

| Вакансия с критериями | Форма IT-вакансии и серверное хранение |
| Приём резюме | Текст, PDF, DOCX, TXT |
| Уточнение неполного резюме | Вопросы по требованиям и сохранение ответов |
| Объяснимый подбор | Навыки, исходные фрагменты и сигналы ML2 |
| Контроль HR | Исправление навыков, заметки, просмотр всех кандидатов и решение |
| Shortlist | Сохранение статуса и экспорт в таблицу |
| Проверка полезности | Сохранение оценки и комментария пользователя |
| Подбор вакансий по резюме | Отдельный сценарий кандидата на том же pipeline |

Назначение интервью, ATS-интеграции, платежи и автоматические отказы в ядро MVP не включены. Работа с реальными пользователями и показатели точности не подменяются демонстрационными данными.

Для сдачи задания дополнительно нужна аналитическая часть: проблема, аудитория, конкуренты, SWOT, customer journey, приоритеты функций, подход разработки и результаты настоящего alpha/beta-тестирования минимум с 10–15 потенциальными пользователями. Код покрывает прототип; он не заменяет исследование и итоговый PDF.

Для пользовательского тестирования дайте участнику одну одинаковую IT-вакансию и набор резюме, попросите собрать shortlist вручную и с MVP. Записывайте время на кандидата, ручные исправления, завершённые уточнения, пропущенных подходящих кандидатов и комментарии. Результаты следует внести после проведения теста; вымышленных отзывов, замеров экономии времени и заявленной точности в проекте нет.
